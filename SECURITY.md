# Reporting security issues

Do not publish credentials, email contents or exploit details in public issues. Contact the repository owner privately through an existing trusted channel. If GitHub private vulnerability reporting is enabled, use Security → Report a vulnerability. A dedicated security contact and response SLA have not yet been established.

Include the affected commit, minimal reproduction using synthetic data, expected/actual behaviour and impact. Do not test against other users or live mailboxes without permission.

This is an initial release without an independent security audit or formal supported-version policy. See [security controls and limitations](docs/SECURITY.md) and [validation](docs/VALIDATION.md).
